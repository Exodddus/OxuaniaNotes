# Chap 5: Thread-Level Parallelism — Coherence

***"本章核心"***

- 从 **ILP** 转向 **TLP**：并行性的识别从硬件窗口上升到软件/程序员划分的线程
- 多处理器与 **MIMD**，以及两种共享内存组织：集中式 **SMP/UMA** 与分布式 **DSM/NUMA**
- 并行处理的两大障碍：程序并行度有限、远程通信代价高
- 高速缓存一致性：coherence、consistency 与写串行化
- 监听式一致性：写无效、写更新，及 **MSI/MESI/MOESI/MESIF**
- 一致性失效：真共享失效与伪共享失效
- 目录式一致性：目录状态、Sharers 位向量、家节点与状态转换

## ILP → TLP

### ILP → TLP

**指令级并行**（instruction-level parallelism, **ILP**）主要由处理器在有限的指令窗口中发现；**线程级并行**（thread-level parallelism, **TLP**）则由软件系统或程序员在更高层次上识别。

- ILP 的并行单位是单条指令，典型手段包括流水线、多发射、乱序执行和推测执行。
- TLP 的并行单位是线程；一个线程通常包含成百上千乃至数百万条指令。
- 要充分利用具有 $n$ 个处理器的系统，通常至少需要 $n$ 个可同时运行的线程或进程。
- 线程的**粒度**（grain size）必须足够大，否则创建、调度、同步和通信的开销会抵消并行收益。

### MIMD — Multiple Instruction Streams, Multiple Data Streams

TLP 通常依赖 **MIMD**：每个处理器独立取指，执行自己的指令流，并处理自己的数据流。不同处理器可以运行同一程序的不同线程，也可以运行完全不同的程序。

### Multiprocessors — Multiple Instruction Streams, Multiple Data Streams

**多处理器**（multiprocessor）是由一组紧密耦合的处理器构成的计算机系统：

- 通常由同一个操作系统统一管理和协调；
- 通过共享地址空间交换数据；“共享内存”首先指地址空间共享，不要求所有内存都位于同一物理位置；
- 可以是单芯片上的多核（multicore），也可以由多个多核芯片组成。

### Exploiting TLP

利用 TLP 有两种主要的软件模型：

- **并行处理**（parallel processing）：多个紧密协作的线程共同完成一个任务。
- **请求级并行**（request-level parallelism）：多个相对独立的进程或请求并行执行，请求可来自一个或多个用户。

## 课件结构（Outline）

课件依次讨论三部分：

1. **Multiprocessor Architecture**：多处理器架构及并行处理的障碍；
2. **Centralized Shared Memory**：集中式共享内存、监听一致性协议及其扩展；
3. **Distributed Shared Memory**：分布式共享内存与目录式一致性协议。

## Multiprocessor Architecture

按照内存组织与互连方式，共享地址空间的多处理器可分为两类：

- **对称/集中式共享内存多处理器**（SMP）；
- **分布式共享内存多处理器**（DSM/DMP）。

### Centralized Shared-Memory

集中式共享内存系统通常适用于规模较小的多处理器，课件给出的典型范围是 **32 核或更少**。

- 所有处理器共享一套集中式物理内存，并具有相同的访问权限。
- 从各处理器看，访问任意主存位置的延迟基本一致，因此又称 **统一内存访问**（uniform memory access, **UMA**）系统。
- 每个处理器可以拥有私有缓存，而较低层缓存或主存由所有处理器共享。
- 优点是编程模型与一致性实现相对简单；缺点是共享总线、共享缓存和内存带宽容易成为集中式瓶颈。

### Distributed Shared Memory

为了支持更多处理器，内存可物理分散到不同节点，每个节点由处理器、缓存和本地内存组成。

- **本地内存访问**延迟低，**远程内存访问**必须经过互连网络，延迟更高。
- 访问时间取决于数据的物理位置，因此称为 **非统一内存访问**（nonuniform memory access, **NUMA**）。
- 分布式内存提高了总内存带宽，并减少本地访问延迟，扩展性优于集中式组织。
- 代价是处理器间通信更复杂，软件需要重视数据放置、局部性与负载划分。

??? info "SMP 与 DSM 的共同点"

    两者都向软件提供共享地址空间，线程仍可用普通的 load/store 访问共享数据；差异主要在物理组织、访问延迟和一致性协议的实现方式。

## Hurdles of Parallel Processing

并行处理有两类核心障碍：

1. **程序中的并行能力有限**（limited parallelism）；
2. **通信代价较高**（high communication cost），尤其是远程内存访问延迟。

### Limited Program Parallelism

程序中的数据相关、控制相关和串行阶段都会限制同时可用的线程数。即使拥有很多处理器，不能并行化的部分仍决定加速比上限。

#### 例 1：100 个处理器要达到 80 倍加速

设串行比例为 $f$，由 Amdahl 定律：

$$
80=\frac{1}{f+\frac{1-f}{100}}
$$

解得：

$$
f\approx0.0025=0.25\%
$$

也就是说，若想用 100 个处理器取得 80 倍加速，串行部分必须压到约 **0.25%**。

#### 例 2：程序可使用 1、50 或 100 个处理器

程序有 95% 的时间使用全部 100 个处理器。设原执行时间中有 $x$ 的比例使用 50 个处理器，其余 $0.05-x$ 只能使用 1 个处理器。若目标加速比为 80，则：

$$
\frac{1}{80}=\frac{0.95}{100}+\frac{x}{50}+(0.05-x)
$$

解得 $x\approx4.8\%$，即剩余 5% 中约 **4.8%** 必须能使用 50 个处理器，只能串行执行的比例约为 **0.2%**。

### High Communication Cost

并行线程需要交换数据、维护一致性并进行同步；远程访问可能比本地运算慢数百个周期。

课件示例：32 处理器系统中，远程访问需要 $100\text{ ns}$，时钟频率为 $4\text{ GHz}$，基础 CPI 为 0.5，远程访问比例为 0.2%。

- 一次远程访问的代价：$100\text{ ns}\times4\text{ GHz}=400$ 周期；
- 平均附加 CPI：$0.2\%\times400=0.8$；
- 实际 CPI：$0.5+0.8=1.3$；
- 若没有通信开销，性能将是当前的 $1.3/0.5=2.6$ 倍。

即使远程访问比例只有 **0.2%**，也足以显著拖慢程序。

### Improve Parallel Processing

针对两类障碍，可分别优化：

- 并行度不足：采用并行性更好的算法，改善任务分解、负载均衡和调度，使更多时间处于“全处理器工作”状态；
- 远程通信延迟：用缓存共享数据、优化数据布局和局部性，并用多线程或预取隐藏延迟。

## Centralized Shared-Memory

大容量、多级缓存能显著降低处理器对共享内存带宽的需求。共享内存系统中的数据可分为：

- **私有数据**：只由一个处理器使用，缓存只会迁移其位置，不会产生处理器间一致性问题；
- **共享数据**：由多个处理器访问，可复制到多个私有缓存中，从而降低延迟、内存带宽需求和读取竞争。

共享数据的复制带来新问题：若某个处理器修改了自己的缓存副本，其他处理器可能继续读到旧值。

## Cache Coherence Problem

高速缓存一致性问题来自两种状态并存：

- 主存定义的**全局状态**；
- 各处理器私有缓存定义的**局部状态**。

若不采取额外措施，不同处理器可能对同一地址观察到不同的值。直观地说，一个一致的内存系统应让读取返回该数据项最近一次写入的值；但这个说法还需拆成两个概念：

- **一致性**（coherence）：一次读取允许返回哪些值，主要约束同一地址；
- **连贯性**（consistency）：写入值何时必须对读取可见，涉及不同地址操作之间的次序。
	- ***Memory consistency?*** 

### Coherence Property: 1/3

处理器 $P$ 写入地址 $X$ 后再读取 $X$，若两者之间没有其他处理器写 $X$，该读取必须返回 $P$ 刚写入的值。这保证了单处理器内部的**程序顺序**。

### Coherence Property: 2/3

一个处理器写 $X$ 后，另一个处理器经过足够充分的时间间隔后读取 $X$，若期间没有其他写入，该读取必须得到新值。处理器不能永远看到过时副本。

### Coherence Property: 3/3

对同一地址的写入必须满足**写串行化**（write serialization）：所有处理器都以相同顺序观察这些写入。例如，若两个写入的全局次序是 1 后 2，就不能有处理器先看到 2、后来又看到 1。

## Consistency

一致性并不要求远程写入瞬间可见。写入数据可能尚未离开源处理器，因此系统还需要内存连贯性模型规定“何时可见”。本课件的重点是 cache coherence；更广义的 memory consistency 需要额外规定不同地址读写能否乱序。

## How to Enforce Coherence?

### Cache Coherence Protocols

一致性协议的关键是追踪每个缓存块的共享状态。主要有两种方案：

- **基于目录**（directory based）：在一个确定的位置记录块的状态、所有者和共享者；
- **监听**（snooping）：各缓存控制器持续监听共享互连上的事务，检查本地是否持有相应缓存块。

集中式、小规模系统适合监听；规模扩大后，为避免广播，通常采用分布式目录。

## Snooping Coherence Protocol

监听协议中，每个缓存都观察总线或广播介质上的地址和请求。两种基本写策略如下。

### Write Invalidate Protocol

**写无效协议**（write invalidate）要求处理器在写入共享块前取得独占权，并使其他缓存中的副本失效。

- 写者取得总线后广播待无效化的地址；
- 其他处理器持续监听总线，若本地命中该地址，就把对应缓存块置为无效；
- 后续读取该块的处理器将发生失效，并从内存或持有最新副本的缓存取回数据；
- 多个处理器竞争写同一块时，总线/互连会将请求串行化，从而保证写串行化。

写无效适合“一写多读”或同一处理器连续多次写的场景，因为取得独占权后，后续本地写不再占用总线。

#### Write Update/Broadcast Protocol

**写更新/写广播协议**（write update/broadcast）在每次写共享数据时广播新值，更新其他缓存中的所有副本。读者较快获得新值，但每次写都消耗互连带宽，因此现代多处理器通常更偏向写无效协议。

#### 写穿式与写回式缓存

- **写穿式**缓存总是同步更新内存，失效后可直接从内存读取最新值，实现简单但带宽开销大。
- **写回式**缓存的最新值可能只在某个私有缓存中。若某缓存监听到读请求且持有脏副本，它必须提供数据，并中止原本的内存或 L3 访问。

### How to Implement?

每个核心内设置一个**有限状态控制器**，同时处理：

- 本地处理器发出的读/写请求；
- 总线或互连上监听到的请求；
- 缓存块状态改变；
- 数据访问、写回与无效化事务。

逻辑上，每个缓存块都有自己的状态机；硬件控制器则让多个块的事务交错进行。

### MSI：三状态写无效协议

| 状态               | 含义              | 内存是否最新 | 其他缓存可有副本 |
| ---------------- | --------------- | ------ | -------- |
| **M — Modified** | 本缓存持有已修改的唯一副本   | 否      | 否        |
| **S — Shared**   | 本缓存持有干净、可能共享的副本 | 是      | 是        |
| **I — Invalid**  | 本缓存中的该块无效       | —      | 可以       |

### How Do States Transit?

#### 本地处理器请求

| 当前状态 | 本地操作 | 动作与新状态 |
| --- | --- | --- |
| I | 读 | 发出 BusRd，取得数据，进入 S |
| I | 写 | 发出 BusRdX/写无效，取得独占副本，进入 M |
| S | 读 | 本地命中，保持 S |
| S | 写 | 广播无效化，其他副本变 I，本块进入 M |
| M | 读/写 | 本地命中，保持 M，不需要总线事务 |

#### 监听到的总线请求

| 当前状态 | 总线事件    | 动作与新状态           |
| ---- | ------- | ---------------- |
| S    | 其他核读    | 保持 S             |
| S    | 其他核写/升级 | 本块失效，进入 I        |
| M    | 其他核读    | 提供或写回最新数据，转为 S   |
| M    | 其他核写    | 提供或写回最新数据，本块进入 I |
| I    | 任意监听事件  | 无需动作，保持 I        |

??? warning "原子性"

    基础状态图常假设一次一致性事务是原子的。实际系统必须保证竞争同一缓存块的请求被严格排序，否则可能出现瞬态、竞争甚至协议死锁；实现中通常还会加入瞬态状态。

## MSI Extensions: MESI

**MESI** 在 MSI 上增加 **E — Exclusive**：该块只存在于一个缓存中，但仍是干净的，内存副本最新。

- E 遇到本地读：保持 E；
- E 遇到本地写：静默地转为 M，不必广播无效化；
- E 遇到其他处理器读：转为 S；
- 优势是优化“先读入、随后由同一核心写入”的私有化数据。

## MSI Extensions: MOESI

**MOESI** 在 MESI 上增加 **O — Owned**：该缓存是脏共享块的所有者，主存副本已经过时，其他缓存可以持有 S 副本。

- 当其他处理器读取 M 块时，原缓存可由 M 转为 O，直接把数据提供给请求者，而不必立刻写回主存；
- O 状态的所有者负责响应后续请求，并在替换该块时写回主存；
- M、O、E 是所有权相关状态；M 与 E 表示排他性；M 与 O 表示主存中的块可能不是最新值；除 I 外的状态都表示本地副本有效。

## MESI Example

分析 MESI 访问序列时，可按以下顺序判断：

1. 先看本地状态，判断命中还是失效；
2. 再看是否需要 BusRd、BusRdX 或升级/无效化事务；
3. 判断其他缓存是否持有副本，决定读入后是 E 还是 S；
4. 最后同步更新请求者与监听者的状态。

关键分界：第一次读取且没有其他副本时进入 **E**；若已有其他副本则进入 **S**；E 上的本地写只需静默转为 **M**。

## MESIF

**MESIF** 在 MESI 上增加 **F — Forward**。当多个缓存都处于共享状态时，F 指定由哪个缓存响应新的读请求，避免多个共享者同时发送相同数据。

- F 仍然是干净、可共享的有效副本；
- 通常最近一次请求该缓存行的处理器被指定为新的 F；
- 它优化的是共享数据的响应者选择，而不是数据写权限。

## How to De-bottleneck?

随着核心数和内存请求量增加，共享总线、监听标签端口、共享 L3 和内存带宽都会成为瓶颈。解决方向是增加互连与监听带宽，并减少不必要的广播。

## Increase Snoop Bandwidth

提高监听带宽的手段包括：

- **复制标签**：处理器访问一份标签，监听逻辑查询另一份，减少端口竞争；
- **分布式最外层缓存**：把 L3 划分为多个 bank，每个节点只处理一部分地址空间的监听请求；
- **在 L3 设置目录过滤器**：仅向可能持有副本的私有缓存发送请求，而不是广播给所有核心；
- 使用多总线、互连网络和多 bank 缓存，提高总内存带宽。

若 L3 的目录要准确过滤 L1/L2 请求，通常要求 L3 具备**包容性**（inclusion）：上层私有缓存中的块必须能在 L3 找到对应记录。

## Coherence Miss

除强制、容量和冲突失效外，多处理器还会产生**一致性失效**（coherence miss）。

### True Sharing Miss

**真共享失效**来自对同一个数据字的实际通信：

- 处理器第一次写共享块，为取得所有权而触发无效化；
- 另一个处理器随后读取该块中已被修改的数据字，需要重新取得新值。

无论缓存块多小，只要处理器确实交换同一数据字，这类失效就存在。

### False Sharing Miss

**伪共享失效**来自缓存块粒度：两个处理器访问的是同一缓存块中的不同数据字，但一个字的写入会使整个块失效，从而使另一个处理器的无关访问也发生失效。

- 根因是每个缓存块通常只有一组一致性状态位；
- 若缓存块缩小到单个字，且线程并未访问彼此的数据字，这类失效便不会发生；
- 常用软件优化是让不同线程频繁写入的数据分离到不同缓存行，例如填充（padding）或重新布局结构体。

课件示例中 5 次访问的分类依次为：**真共享、伪共享、伪共享、伪共享、真共享**。判断标准不是“块是否共享”，而是“触发失效的写入字是否正是另一处理器随后需要的字”。

## Distributed Shared Memory

监听协议要求所有缓存观察广播，扩展性有限。DSM 把内存和带宽分散到多个节点；为了让一致性机制也能扩展，需要用目录把广播改为定向消息。

- 每个节点为自己负责的物理地址维护目录；
- 目录记录哪些缓存持有副本，以及数据是否被修改；
- 一个内存块的目录信息始终位于可由物理地址确定的唯一位置；
- 缓存失效时只联系实际共享者，无需向所有节点广播。

## Directory-based Cache Coherence Protocol

### 节点角色

- **本地节点**（local/requesting node）：发起读写请求的节点；
- **家节点**（home node）：保存该物理地址的内存块与目录条目的节点；
- **远程节点**（remote node）：持有该块缓存副本的其他节点，可能是共享者或所有者。

物理地址映射决定家节点，因此任意请求都能定位到唯一目录。

### 目录状态

| 状态 | 含义 | 内存副本 |
| --- | --- | --- |
| **Uncached** | 没有节点缓存该块 | 最新 |
| **Shared** | 一个或多个节点持有干净副本 | 最新 |
| **Modified** | 只有一个所有者持有已修改副本 | 过时 |

目录还维护 **Sharers 位向量**：在 Shared 状态下，它指出全部共享者；在 Modified 状态下，它可编码唯一所有者。

### 主要消息

- **Read miss**：请求读取缓存块；
- **Write miss**：请求取得可写的独占副本；
- **Invalidate**：使一个或多个共享者的副本失效；
- **Fetch / Data value reply**：向所有者取回数据并返回请求者；
- **Data write-back**：所有者替换脏块时写回家节点。

课件中的符号：$P$ 表示请求节点编号，$A$ 表示请求地址，$D$ 表示数据内容。

## Directory Protocol

### 单个缓存块的状态转换

从请求节点的私有缓存看，I/S/M 的基本转换与监听式 MSI 相近；区别在于请求发送给家节点目录，由目录选择性联系共享者或所有者，而不是在总线上广播。

### 目录状态转换

| 当前目录状态 | 请求 | 目录动作与新状态 |
| --- | --- | --- |
| Uncached | Read miss | 从内存返回数据，把请求者加入 Sharers，转 Shared |
| Uncached | Write miss | 从内存返回数据，请求者成为唯一所有者，转 Modified |
| Shared | Read miss | 从内存返回数据，加入请求者，保持 Shared |
| Shared | Write miss | 向旧 Sharers 发送无效化，返回数据，仅保留请求者，转 Modified |
| Modified | Read miss | 向原所有者 Fetch；原所有者降为 Shared，数据更新内存并发给请求者；两者进入 Sharers，转 Shared |
| Modified | Write miss | 向原所有者 Fetch+Invalidate，把数据转发给新请求者；更新唯一所有者，保持 Modified |
| Modified | Data write-back | 更新内存，清空所有者/Sharers，转 Uncached |

??? note "家节点也不能跳过目录"

    即使请求者就是家节点，也必须查询目录，因为最新数据可能位于某个远程所有者的私有缓存中。课件还专门展示了“家节点读取远程节点持有的块”和“家节点写入并使远程副本失效”的情形。

## Review

- **Multiprocessor architecture**：MIMD 多处理器通过 TLP 利用并行性；SMP/UMA 简单但扩展性有限，DSM/NUMA 可扩展但通信复杂。
- **Cache coherence**：同一地址必须满足读己之写、最终看到远程写，以及写串行化。
- **Write invalidate protocol**：写前取得独占权并使其他副本失效，是现代系统的主流。
- **Write update/broadcast protocol**：写时更新所有副本，读延迟低但带宽代价高。
- **MSI/MESI/MOESI/MESIF**：分别引入 M/S/I、干净独占 E、脏共享所有者 O、共享响应者 F。
- **True/false sharing miss**：前者是真正的数据通信，后者源于缓存块内无关数据互相牵连。
- **Directory-based cache coherence protocol**：目录以状态和 Sharers 精确定位副本，用定向消息替代广播。

??? success "一条主线串起来"

    共享数据被复制到私有缓存以降低延迟 → 写入使副本可能不一致 → 一致性协议追踪块的状态与所有者 → 小规模系统可让所有缓存监听广播 → 规模增大后广播和标签带宽成为瓶颈 → 分布式目录只联系真实共享者，从而提高扩展性。
