# 1. 模型概览

VGGT（通常指论文 **Visual Geometry Grounded Transformer**）是一个面向三维视觉重建的统一大模型。它希望用**单个前馈 Transformer**，直接从一组场景图像中同时预测多个核心 3D 几何量，包括：

- 相机内外参
    
- 深度图（depth maps）
    
- 点图（point maps）
    
- 跨视角点轨迹（point tracks）
    

论文的核心思想是：不再把三维重建拆成“特征匹配 -> 三角化 -> BA 优化 -> 深度/点云恢复”等多个传统模块，而是把这些彼此相关的几何量交给**同一个模型**联合预测。作者强调，VGGT 虽然只引入了很少的 3D 归纳偏置，但在大规模 3D 标注数据上训练后，已经能在多项三维任务上直接输出高质量结果，而且推理速度很快。

从定位上看，VGGT 有点像把 3D 视觉中的多个经典子任务，统一放进了一个“几何基础模型（geometry foundation model）”里。

# 3. VGGT 要解决什么问题

传统三维视觉系统通常是“流水线式”的：

1. 先做特征提取与图像匹配
    
2. 再估计相机姿态
    
3. 再恢复稀疏/稠密几何
    
4. 最后通过 BA（bundle adjustment）等优化精修
    

这类方法的优点是物理约束清晰、可解释性强，但缺点也很明显：

- 管线长，模块之间误差会传递
    
- 多阶段优化比较慢
    
- 往往针对单一任务分别设计系统
    
- 对纹理稀疏、遮挡、跨域数据等情况较脆弱
    

VGGT 的目标是把这些步骤“神经网络化、统一化”。给定一个场景的一张、几张，甚至上百张图像，模型一次前向就输出整个场景的关键几何属性。这种设计的价值在于：

- 让多个几何任务共享表征
    
- 利用任务之间的约束提升整体精度
    
- 降低对复杂后处理和迭代优化的依赖
    
VGGT 处理的结果可以用在下游任务中，例如动态视频中物体追踪和新视角生成。

# 4. 输入与输出定义

## 4.1 输入

VGGT 的输入是一个图像集合：

$$
\mathcal{I} = (I_i)_{i=1}^{N}
$$

其中 $N$ 可以很小，也可以达到几十乃至上百。论文特别强调，该模型能处理“one, a few, or hundreds of views”。

输入序列中，**第 1 张图像被当作参考视角**。除第 1 帧外，其余帧在模型设计上基本满足置换等变（permutation equivariant），也就是说它不依赖严格的时间顺序，这一点很适合一般的多视图场景，而不仅仅是视频。

## 4.2 输出

VGGT 联合预测以下量：

### 1. 相机参数

每个视角的相机参数记为：

$$
g_i = [q_i, t_i, f_i]
$$

其中：

- $q_i$：旋转四元数
    表示相机在空间中的**旋转**。更加紧凑而且容易保持旋转的连续性。
- $t_i$：平移向量
	描述相机中心在 3D 空间中的**位置坐标** $(x, y, z)$。
- $f_i$：视场参数（field of view）
    水平和垂直方向的**视野范围**，与相机的焦距和主点有对应关系。不过论文中默认主点位于图像中心，这与很多 SfM 系统中的近似一致。

### 2. 深度图

每个像素对应一个深度值 $D_i(y)$，表示该像素在第 $i$ 个相机坐标系下的深度。

### 3. 点图

点图 $P_i(y)\in \mathbb{R}^3$ 为每个像素预测三维点坐标。这里有个很关键的设定：

- VGGT 的点图是**视角不变的（viewpoint-invariant）**
    
- 这些三维点都表达在**第 1 个相机的坐标系**中
    

这意味着不同视角下预测的点图，本质上都落在同一个“世界参考系”里，便于跨图像对齐和联合建模。

### 4. 点轨迹

对于查询图像中的某个点，模型还可以预测它在所有其他图像中的对应位置，形成跨视角点轨迹。这让 VGGT 不只适用于静态几何恢复，也能为跟踪、动态场景分析等任务提供通用特征。

# 5. 核心架构

VGGT 的架构可以概括为：

**图像 token 化 + 少量专用 token + 交替式注意力骨干 + 多头几何预测**

## 5.1 图像 token 化：用 DINOv2 做 patchify

论文和附录说明，作者探索过两种 token 化方式：

- 直接用 $14\times14$ 卷积做 patch embedding
    
- 使用预训练 DINOv2 模型提取 patch tokens
    

最终作者选择了 **DINOv2**，原因是：

- 精度更好
    
- 训练更稳定
    
- 对学习率等超参数更不敏感
    

这一步可以理解为：VGGT 没有从像素开始“硬学”几何，而是站在强视觉表征模型 DINOv2 的肩膀上，让 backbone 更专注于多视图几何关系建模。

## 5.2 专用 token：camera token 与 register tokens

对每张输入图像，除了图像 tokens 外，VGGT 还会附加：

- 1 个 `camera token`
    
- 4 个 `register tokens`
    

其中：

- `camera token` 用于汇聚该视角的相机参数相关信息
    
- `register tokens` 类似一组可学习的辅助槽位，帮助 Transformer 存储和交换中间几何上下文
    

论文还特别说明，第 1 帧使用一组与其他帧不同的可学习 camera/register tokens，这与“第 1 帧是参考坐标系”的设定保持一致。

## 5.3 交替式注意力：frame-wise attention + global attention

这是 VGGT 最关键的结构设计之一。模型主干并不是简单把所有图像 token 全部扔进一个标准 Transformer，而是**交替使用两类自注意力层**：

- `frame-wise attention`
    
- `global attention`
    

它们的直观作用可以理解为：

### frame-wise attention

- 主要在单帧内部建模
    
- 强化每张图内部的局部和全局视觉结构
    
- 有利于提取与深度、边界、表面布局相关的表征
    

### global attention

- 在不同图像之间传播信息
    
- 建立跨视角对应、相对姿态与共同三维结构
    
- 相当于让网络直接学习“多视图几何推理”
    

## 5.4 为什么这种交替注意力有用

这里可以做一个合理理解：

- 如果只做单帧建模，模型更像单目深度网络，难以稳定恢复跨视角一致几何
    
- 如果从一开始就全局混合所有 token，计算量大，而且局部视觉结构可能不容易先收敛
    

因此，VGGT 采用“先单帧消化、再跨帧对齐、再回到单帧细化”的交替机制，在效率和表达能力之间做了较好的折中。这也是论文中少数显式保留的 3D 归纳偏置之一。

# 6. 多任务预测头设计

## 6.1 相机头（Camera Head）

Transformer 主干输出后，每张图对应的 `camera token` 被送入相机头，用来预测：

- 旋转四元数
    
- 平移
    
- 视场参数
    

这相当于把“相机姿态估计”变成 token 级回归问题。

## 6.2 稠密输出头：DPT Head

对于深度图和点图，VGGT 使用了 **DPT（Dense Prediction Transformer）风格的头部**。它把 Transformer 产生的特征进一步解码为稠密二维图。

DPT 头会输出：

- 深度图
    
- 点图
    
- 稠密 tracking features
    
- 深度与点图对应的 aleatoric uncertainty maps
    

这里的 uncertainty map 很重要，因为它并不只是附带输出，而是直接参与训练损失，用来表达模型对不同像素预测的不确定性。

## 6.3 跟踪头：基于 CoTracker2

VGGT 并不直接用 Transformer 主干输出最终点轨迹，而是让主干先输出稠密 tracking features，再交给一个基于 **CoTracker2** 的跟踪模块做最终轨迹预测。

论文里这个设计有两个含义：

- 几何 backbone 与跟踪模块可以联合训练
    
- VGGT 的通用几何特征能直接支持更强的点跟踪能力
    

这也说明 VGGT 不只是“重建模型”，还是一个可迁移到下游视觉几何任务的通用表征骨干。

# 7. 点图、深度和相机之间的关系

VGGT 一个很有意思的特点是：它会输出一些**并不完全独立**的量。论文将其称为 **over-complete predictions**。

例如：

- 有了相机参数和深度图，可以恢复对应三维点
    
- 有了点图，在一定条件下也可以通过 PnP 等方法反推相机参数
    

作者发现，这种“冗余联合预测”并没有浪费，反而能帮助整体学习，因为多个几何任务在训练时形成了相互约束。

更重要的是，论文指出：

- 虽然模型单独有 point map head
    
- 但在推理时，**通过单独预测的 depth + camera 再推导 point map，往往比直接使用 point map head 更准**
    

这说明 VGGT 的训练策略本质上更像是“用多任务监督塑造共享几何表征”，而不是要求每个输出头都在推理时独立最优。

# 8. 训练目标

VGGT 使用端到端多任务损失：

$$
\mathcal{L} = \mathcal{L}_{camera} + \mathcal{L}_{depth} + \mathcal{L}_{pmap} + \lambda \mathcal{L}_{track}
$$

其中论文给出的 $\lambda = 0.05$。

### 8.1 相机损失

相机参数使用 **Huber loss** 监督预测相机与真实相机之间的差异。

### 8.2 深度损失

深度损失借鉴 DUSt3R 的 aleatoric uncertainty 形式，同时增加梯度项。可以理解为由两部分组成：

- 像素值误差
    
- 深度梯度误差
    

再由预测的不确定性图进行自适应加权。

这样做的好处是：

- 平坦区域关注整体数值正确
    
- 边缘区域关注几何梯度与结构连续性
    
- 不确定区域不会像确定区域那样被强行拟合
    

### 8.3 点图损失

点图损失与深度损失形式类似，也是：

- 点坐标误差
    
- 点图梯度误差
    
- 不确定性正则项
    

### 8.4 跟踪损失

跟踪头使用对应点位置误差进行监督，并额外引入 visibility loss（二元交叉熵）来判断该点在某帧中是否可见。

这让模型不仅知道“点在哪里”，还知道“点是否应该出现”。

# 9. 坐标规范化（非常关键）

三维重建有一个经典歧义：如果把整个场景做刚体变换，甚至整体缩放，只要投影关系不变，图像本身并不会变化。因此，模型训练时若不固定参考系，就会遇到监督目标不唯一的问题。

VGGT 的做法是显式进行**坐标规范化**：

1. 先把所有量表达在第 1 个相机坐标系下
    
2. 再根据点图中三维点到原点的平均欧氏距离做尺度归一化
    
3. 用这个尺度去归一化平移、点图和深度
    

作者特别指出，他们不是像一些方法那样只对输出后处理，而是把这种“规范化后的目标”直接作为训练监督，让模型学会输出一个固定 canonical form。

这是 VGGT 能稳定进行多任务统一几何预测的重要基础。

# 10. 训练配置与数据规模

根据论文实现细节：

- 主干层数：`L = 24` 组 frame-wise / global attention
    
- 模型规模：约 `1.2B` 参数
    
- 优化器：`AdamW`
    
- 训练步数：`160K iterations`
    
- 学习率策略：cosine scheduler，峰值学习率 `2e-4`，warmup `8K`
    
- 每个 batch：随机采样 `2-24` 帧
    
- 输入最大尺寸：最长边约 `518`
    
- 训练硬件：`64 x A100`
    
- 训练时长：约 `9 天`
    

训练数据覆盖了大量真实与合成 3D 数据集。论文列出的数据包括：

- Co3Dv2
    
- BlendMVS
    
- DL3DV
    
- MegaDepth
    
- Kubric
    
- WildRGB
    
- ScanNet
    
- HyperSim
    
- Mapillary
    
- Habitat
    
- Replica
    

这类混合数据策略非常关键，因为 VGGT 要统一处理：

- 室内与室外
    
- 真实照片与合成图像
    
- 少视图与多视图
    
- 静态重建与可迁移跟踪表征
    

# 11. VGGT 相比传统方法的技术意义

## 11.1 从“优化式几何”到“前馈式几何”

传统 SfM/MVS 很大程度依赖显式优化，例如：

- 匹配质量决定初始化
    
- BA 决定最终精度
    
- 稠密重建需要额外阶段
    

VGGT 则把大量几何知识压进参数中，尽量通过单次前向完成场景解释。它并不是彻底否定优化，而是把优化从“必须项”降成“可选增强项”。

## 11.2 从单任务模型到统一几何基础模型

过去常见的是：

- 单目深度模型只做深度
    
- 相机姿态模型只做位姿
    
- 跟踪模型只做跟踪
    

VGGT 的贡献在于表明：这些任务共享一个足够强的几何 backbone 是可行的，而且联合学习能互相增益。

## 11.3 少归纳偏置但保留关键结构先验

VGGT 没有手工嵌入很多传统三维几何模块，但也不是完全“无偏置”：

- 第 1 帧被固定为参考系
    
- 交替 frame/global attention 体现了多视图结构先验
    
- camera token / register tokens 提供了结构化信息槽位
    
- 点图采用统一参考系表达
    

这是一种很现代的大模型设计思路：**尽量少写死规则，只保留最关键的结构约束，其余交给数据驱动学习。**

# 12. 这套方法为什么可能有效

这里给出一个偏“机制解释”的总结。

## 12.1 多任务共享让几何表征更稳

如果一个像素的表示同时要服务于：

- 深度预测
    
- 三维点坐标预测
    
- 相机姿态估计
    
- 跨视图对应
    

那么 backbone 被迫学到更接近真实几何结构的特征，而不是只适合某一个单独任务的捷径特征。

## 12.2 大规模数据让模型学到“隐式 BA”

传统 BA 是显示地做重投影一致性优化。VGGT 虽然不是在测试时显式迭代优化，但在海量场景上训练后，模型参数里可能学到了大量“多视图一致性”的统计规律。可以把它理解为一种**前馈近似的几何优化器**。

这是理解 VGGT 的一个重要视角。

## 12.3 冗余监督增强鲁棒性

即使点图、深度、相机之间存在冗余，联合监督依然有价值，因为：

- 某些数据集相机更可靠
    
- 某些数据集深度更可靠
    
- 某些局部区域跟踪信号更强
    

多个目标共同训练，会促使模型在信息不完整时通过其他分支进行补偿。

# 13. 可能的局限

虽然 VGGT 很强，但从论文描述和方法结构看，也存在一些潜在限制：

## 13.1 训练成本高

1.2B 参数、64 张 A100、9 天训练，说明这不是一个容易低成本复现的模型。

## 13.2 统一模型不等于每个子任务都绝对最优

统一 backbone 能带来整体收益，但在某些极端专用场景中，专门为单任务设计的模型仍可能更强。

## 13.3 对训练数据覆盖面仍然敏感

VGGT 很大程度依赖多种 3D 标注数据共同塑形。如果遇到训练分布外的传感器、镜头模型、极端场景或强动态内容，性能仍可能下降。

## 13.4 点图头并非总是最佳推理路径

论文自己就指出，推理时由 `depth + camera` 派生 point map 可能更优，这意味着“训练时联合预测”和“测试时最佳使用方式”并不总是完全一致。

# 14. 一句话总结

VGGT 的本质可以概括为：

> 用 DINOv2 token 化的多视图图像作为输入，通过交替的单帧/跨帧 Transformer 主干学习统一几何表征，再以多任务方式联合预测相机、深度、点图和点轨迹，从而把传统三维视觉中的多阶段优化管线压缩为一个大规模前馈几何模型。

如果你后续要把这份文档继续浓缩成课程报告或组会汇报，可以直接用下面这段：

VGGT 提出了一个统一的多视图几何基础模型框架。与传统 SfM/MVS 依赖多阶段优化不同，它通过一个 1.2B 参数的前馈 Transformer，在大规模 3D 标注数据上联合学习相机估计、深度恢复、点图预测和跨视角跟踪。其关键设计包括基于 DINOv2 的图像 token 化、camera token 与 register tokens、交替式 frame-wise/global attention 主干，以及结合 DPT 与 CoTracker2 的多任务预测头。该模型表明，多种几何任务可以在统一 backbone 中实现互补学习，从而把经典三维视觉问题推进到“几何基础模型”范式。
